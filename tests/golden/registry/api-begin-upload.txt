usage: mopm api begin-upload <namespace>/<name> <version> --subdir <linux-64|linux-aarch64|osx-arm64|noarch> --filename <filename> --sha256 <sha256> --size <n> [--registry <prod|gamma|beta|url>] [--config-dir <dir>] [--json]

Begin the upload of one file of a version (one step of 'mopm publish').

Publishing is three steps: begin an upload per file (this call), PUT the
bytes to the returned URL with the returned headers, then commit
(`commitPublish`). The registry binds the upload to the caller, the
name, the version, the sha256 and the size; the presigned URL carries a
signed `x-amz-checksum-sha256` and an exact content length so the
storage layer itself rejects any other bytes. The URL expires in at
most five minutes.

A file over the per-file limit is `payload_too_large` (413). A file
that would take the package's live files (published and yanked
versions; a takedown frees its bytes) over the 10 GB per-project limit
is `limit_exceeded` (403), which is about the project, not the file:
a smaller file may still fit.

arguments:
  <namespace>/<name>
      The namespace of the package, a GitHub login in lower case.
      Normalised package name, the part of the full name after the `/`.
  <version>
options:
  --subdir <linux-64|linux-aarch64|osx-arm64|noarch>
      required.
  --filename <filename>
      required.
  --sha256 <sha256>
      required.
  --size <n>
      required. Bytes. At most 100 MB (100,000,000 bytes).
  --registry <prod|gamma|beta|url>
      the registry (default prod)
  --config-dir <dir>
      where 'mopm login' keeps credentials.json (default ~/.config/mopm)
  --json
      print the registry's answer as JSON instead of text

Sends POST /api/v2/packages/{namespace}/{name}/{version}/files (beginUpload) with the token 'mopm login' stored, or $MOPM_TOKEN.
